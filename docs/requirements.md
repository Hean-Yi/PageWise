# 需求基线

日期：2026-11-13。来源：本项目连续需求访谈。

本文记录产品承诺；实现建议和验证方法分别见技术选型与设计文档。

## 已确认

### R01 平台、用户与运行方式

Mac 是主要设备，iPad 支持 Apple Pencil 自由手写；两端都能独立检索、下载、解析、翻译、阅读和问答。第一版不包含 iPhone。面向作者及少量朋友，每人使用自己的资料与 API 配置，不提供团队共享论文库。

最低支持 macOS 15，优先 SwiftUI。无自建服务器；本地处理不代表大模型离线运行，翻译与问答调用用户配置的外部 API。

### R02 论文获取

输入完整或模糊标题。明确且唯一的匹配直接下载；模糊、多候选或版本身份不明确时，展示标题、作者、年份和来源，等待选择。无法获取全文时保留论文信息和来源链接，支持手动 PDF 导入。Mac 必须支持从 Finder 拖拽一个或多个 PDF，导入的本地 PDF 同样进入解析、重排及质量降级流程。

主要论文领域为计算机 / AI。论文检索和实际下载地址必须来自可验证的来源，不能使用模型凭空生成的链接。

### R03 双语重排与降级

英文原段在前，中文译文在后。公式、图表、图注、代码、引用和阅读顺序必须纳入质量检查。无法可靠重排时说明原因并使用普通 PDF 阅读和批注；不能只凭转换程序没有报错就宣称质量合格。

始终保留原始 PDF。重排阅读体验优先于宣称支持所有论文。

### R04 渐进翻译与页面冻结

先解析结构和准备排版，前几段翻译完成即可展示，其余内容在应用运行、用户阅读时继续处理。

用户已同意将最初的“整篇版式冻结”细化为“逐步追加固定页面”：已发布页面不再移动、插入内容或回填空白；完成的后续内容追加在其后。未完成部分可以预览原文，但不允许在尚未固定的重排内容上手写。

允许应用进入后台后暂停，恢复前台后继续；不要求锁屏或切出应用后无限持续翻译。

### R05 手写和文字批注

用户需要直接在重排文章上手写、画箭头、圈选和写公式，不接受仅文字高亮代替自由手写。两端展示同一份固定页面，通过缩放适配窗口；不能在另一设备重新计算版式导致笔迹错位。

划线选文后可询问 AI；普通 PDF 降级模式也能阅读和批注。

### R06 AI 与检索

翻译和问答共用用户在设置中自行配置的大模型 API，优先 GLM，并提供兼容接口；服务地址、模型与密钥都可修改。

划线问题优先结合当前论文全文语境解释选中的文字、公式或图表；整个论文库和用户指定的 Obsidian 目录是辅助资料。回答区分论文原意、其他来源的补充与模型推断，引用可定位。

### R07 Memory

自动整理并更新研究兴趣、知识背景、阅读进展和未解决问题。用户可以查看、修改、删除记忆。记忆保留来源，模型推测需标注。

聊天、原始批注、笔记和阅读事件作为独立记录保存；不是所有历史都必须转成长期记忆。

### R08 Obsidian

现有笔记库位于 iCloud Drive。应用读取用户指定范围用于辅助检索。

每篇论文对应一份 Markdown 笔记；只有点击“保存到 Obsidian”才写入阅读记录、批注和总结。后续保存更新该笔记且保留用户撰写的部分，避免重复追加。

每次保存询问“是否将本次讨论整理到笔记中？”。同意时根据上下文整理读者与 Agent 的问题、解释、讨论结论和未解决问题，而不是默认把聊天原文全部附上。

### R09 阅读日历

自动记录每天阅读的论文、估计阅读时长、批注和笔记活动；用户可补记或修正。跨设备记录合并，避免同一时间段重复计时。

### R10 同步与分发阶段

希望通过各自的 iCloud 账户同步应用资料。现在没有付费 Apple 开发者会员，用户接受软件成熟后再购买。

当前先开发可独立运行的本地功能。CloudKit 自动同步的签名、真机和多账户验证，以及面向朋友的便利分发，安排在会员可用后。同步能力仍属于完整第一版目标，不能把本地阶段宣称为多端同步已经完成。

## 设计默认值，不作为用户已经确认的事实

- iPadOS 18 暂定为最低版本；若用户设备更旧，需要重新确认。
- 当前以英文到简体中文为主；其他语言方向后续扩展。
- API Key 每台设备分别配置，不通过应用数据同步。
- 已下载的页面、原文、笔记和批注离线可读写；联网后才能继续在线翻译和问答。
- 第一阶段提供 GLM 和可配置的 OpenAI 兼容协议适配；不承诺每个同协议服务行为完全相同。
- 自动阅读计时只是估计，长时间无操作与后台时段需保守处理，并允许用户修正。
- 第一阶段不训练或打包本地大语言模型，不依赖另一个付费 embedding 服务。

## 第一版之外

iPhone、多人实时协作、公开 App Store 上架、任意论文无损转换、全自动识别所有手写内容、全天候后台任务、Windows / Android、在设备上执行下载论文附带的 TeX 或代码。

原始手写内容以图像和可编辑笔迹保留；识别或解释图表/手写是否可用取决于所配置模型的视觉能力，不默认认为文本模型能够看图。

## 2026-11-14 界面补充

用户要求整个 App 以视觉引导操作，突出主任务并弱化次要信息；减少解释性文字、重复口号与技术实现细节。通过 Computer Use 检查真实窗口的视觉与操作。
