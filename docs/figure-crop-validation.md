# PDF 图件裁剪与验收

## 已接入的处理

HTML 图片转换失败时，应用先在原始 PDF 中唯一定位图注。文本按坐标重组，兼容源文件倒序绘制、同一行拆成多个片段的情况。图注不能唯一定位时，不猜测页码。

候选页在设备上渲染为最长边不超过 1600 像素的灰度图，使用背景阈值、文字行掩码、4 点网格连通区域、列范围与正文/图注分隔寻找主体。图内标签按接触关系扩展，远端图例、多面板按同一图注范围合并。检查裁剪框是否切过文字、碰到正文或页面边界；通过后按最高 3 倍、最长边 4096 像素生成 PNG。

恢复后的图件保留原 PDF 可见内容和图内文字，图注重新作为可选文字排版并翻译。图形和图注位于固定页，原始 PDF 不改动，补图中间资源在固定页提交后随富内容释放。失败或不确定时保留对应原页，找不到源页时显示提示。已有固定页不重新裁剪。

本轮针对有 HTML 图注的失败图件。上传 PDF 的复杂页仍走整页保留；没有实现扫描件 OCR、任意 PDF 图注识别或用户手动框选。旋转页、图注在图件上方、无可匹配图注、深色背景、正文混排或边界歧义等情况可能拒绝自动裁剪。

## 99% 目标的定义

用户提出 99% 裁剪成功率目标，目前没有代表性、独立标注样本证明已经达到。成功需同时满足匹配到正确图件、图形/图内文字/图例/所有面板完整、未混入相邻正文。只生成一个 PNG、保留原页和拒绝裁剪均不能计为成功。

原创样例用于回归，已用于调参的真实论文用于兼容性验证；两者都不能作为总体成功率的独立估计。发布性能承诺之前，需要固定并分层标注不同出版版式、单/双栏、多面板、图注位置、字体与图形类型，记录误裁和拒绝，另外留出未参与调参的验证集。

## 本地评测工具

在仓库根目录运行，输出目录必须是新的目录。工具只读原 PDF，不调用 API，也不上传资料。

```bash
bash scripts/audit-figure-crops.sh /absolute/original.pdf /absolute/truth.json .local/crop-audit-run
```

工具使用当前 Debug 模块编译内部算法验证器，因此属于 Mac 开发工具；应用中的裁剪算法在 Mac/iPad 本机运行，不依赖此脚本或另一个设备。

`truth.json` 示例（坐标单位是 PDF 点，原点在未旋转页面左下角；`page` 从 1 开始；数值需由原 PDF 人工标注）：

```json
[
  {
    "caption": "Figure 1. Two original panels.",
    "page": 1,
    "expected": {"x": 70, "y": 350, "width": 220, "height": 320},
    "body": [{"x": 50, "y": 720, "width": 500, "height": 20}]
  }
]
```

输出包括 `report.json` 和实际裁剪 PNG。报告区分 `geometric_pass`、`wrong_crop`、`refused`；拒绝包含在总分母中。自动几何规则要求页码正确、真值框覆盖至少 99.5%、裁剪面积不超过真值框 1.5 倍、与标注正文交叠不超过 1 平方点。这些阈值用于发现漏边和多裁，不能代替 PNG 与原页的人工核对，也不等于 99% 的总体成功率。

真值清单应包含约定范围内的全部待恢复图件，不能只收录成功样本。真实论文、标注和输出放在忽略目录或外部目录，不提交到 Git。
