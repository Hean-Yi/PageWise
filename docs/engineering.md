# 代码与工程规范

状态：本地 MVP 已建立应用工程与验证脚本，当前实际检查结果见 [MVP 状态](mvp-status.md)。尚未配置远程 CI。

## 工具链与兼容性

- Swift 6 language mode、SwiftUI、Swift Package Manager。开发工具链暂以当前可用的 Xcode 26.2 / Swift 6.2.3 为基准，最低运行版本与工具链版本分开管理。
- macOS deployment target 为 15.0；iPadOS 暂为 18.0。禁止因使用当前 SDK 而无意提升最低运行版本。
- 新依赖先核对许可证、维护情况、平台和工具链要求；项目生成时锁定实际解析版本并提交 Package.resolved。
- 使用工具链内置 swift-format，4 空格缩进；创建工程时再落地格式配置并核实命令，不预先写不可运行的 CI。
- 类型和协议用 UpperCamelCase，属性与方法用 lowerCamelCase。错误描述面向用户；技术诊断放入不包含原文或密钥的日志。

## 依赖方向与接口

依赖由外向内，领域层不依赖 SwiftUI、PDFKit、CloudKit、数据库或某一模型供应商。

```text
App / Platform UI
        |
        v
Application Use Cases
        |
        v
Domain Models + Ports <--- Infrastructure Adapters
```

按导入、阅读、问答、记忆、笔记、活动记录等业务边界组织；先用清晰目录和少量 Package target 实现，不为每个协议单独建包。

View 负责显示与交互；可观察状态通过 @Observable 和 @MainActor 管理。用例协调工作；Repository 和 Service 协议隔离持久化及外部服务。跨平台共用模型与用例，平台桥接集中放在边缘，避免到处散落条件编译。

依赖从应用入口注入；测试可替换网络、时钟、ID、文件访问和数据库。不使用无法替换的全局单例。

## 目录与文件职责

目录导航与归属标准见 [工程结构](architecture.md)。新增代码先明确职责，再放入领域模型、外部适配、应用协调、功能页面或平台桥接目录。禁止向两个库 target 根目录堆放 Swift 文件，也不以 `Utils`、`Models` 或无边界 `Services` 作为默认分类。

领域模型按业务拆分；应用扩展负责协调已有共享状态；视图按功能聚合；AppKit/UIKit 控件集中在 Platform。文件名应反映主要类型或职责，紧密相关的私有辅助可与主类型同文件。共用测试替身放测试 Support，跨功能测试放 Integration。

目录移动使用 Git 可识别的搬移，拆分保留公开 API 与编码字段。结构调整后核对构建源清单、公开符号、测试清单和当前文档链接，执行完整检查；不为单纯文件移动添加重复实现的测试。

## 并发、任务与网络

- 采用 async/await、actor 和结构化任务。CPU 密集解析不占用主线程；平台要求主线程的渲染调用单独隔离。
- 跨隔离域的数据满足 Sendable。不得用 @unchecked Sendable 或全局关闭检查来掩盖竞争。
- 所有长任务支持取消、进度、失败原因和持久化恢复点；前台问答优先于预翻译和记忆维护。
- 网络配置超时、限流与有上限的退避；401/403、无效参数不盲目重试。尊重 Retry-After；取消不显示为意外故障。
- 模型生成请求可能在网络中断时已计费：保存请求状态，区分确定失败与结果未知；不承诺供应商没有提供的“恰好执行一次”。
- 流式协议处理网络分片、空事件、完成事件和中断；缓存只存校验后的完整输出，不能把半段译文当作完成。

## 持久化和数据不变量

- 数据库迁移显式编号，测试旧版本升级，不在启动时删库重建。
- 每个论文版本、语义块、版式版本、页面、批注、事件和记忆拥有稳定 ID。位置引用必须带版本。
- 原始论文和已发布页面不可变。文件先写入临时路径、校验、原子提交，再提交数据库引用；启动时处理未完成写入和孤立临时文件。
- 更新数据库与同步 outbox 在同一事务完成。未启用云能力时不阻塞本地操作。
- 不把 SQLite / WAL 数据库本体放入 iCloud Drive 让两台设备共同写；检索索引属于可重建的本地数据。
- 可变记录用修订号和父修订表达并发修改；手写冲突保留分支，不采用无提示最后写入覆盖。
- 文件格式和提示模板都有版本；缓存键包含输入哈希、模型配置、提示版本及目标语言。

## 资料、密钥与文件访问

- 设备 Keychain 保存密钥。HTTP 默认 HTTPS；鉴权信息不跨域重定向，不写普通日志，不进入导出文件。
- 下载论文、网页、笔记和检索片段都属于资料，不能覆盖应用指令或触发文件写入、外部调用。
- HTML 必须净化并本地化资源；禁用论文携带的脚本，只执行应用随包提供的渲染代码。
- 文件权限使用系统选择器与有效授权；处理取消、权限撤销、书签失效、文件尚未下载和移动改名。
- Obsidian 更新使用文件协调、内容哈希比较与安全替换；遇到用户修改或冲突保留内容并提供预览。
- 删除记忆保留同步所需的最小墓碑与来源抑制标识，不保存被删除的正文；禁止后续提取同一来源复活该记忆。

## 测试与质量门槛

核心逻辑用 Swift Testing；平台交互和 UI 使用 XCTest / XCUITest。不为纯文档或简单静态配置编写重复实现的测试。

必须覆盖的行为：

1. 追加翻译页面后既有页面哈希和批注坐标不变；重启恢复后相同。
2. 原始/重排页与语义锚点映射正确，公式和图表引用不会跳到其他版本。
3. 中断、429、磁盘不足和不完整输出不会发布损坏页；重复导入和恢复不重复产生已完成结果。
4. RAG 当前论文优先，回答引用来自实际检索证据，超出上下文预算时说明覆盖范围。
5. 删除和用户修正的记忆不被自动提取覆盖；来源失效能被识别。
6. Obsidian 重复保存不重复内容；手写区和修改过的生成区不被静默覆盖；拒绝讨论整理不会新增讨论。
7. 多端阅读时间交集不重复计时；跨午夜、时区和手动修正有明确结果。
8. 云同步启用后，覆盖离线并发、账号切换、缺失附件、删除、冲突、配额和网络中断。

视觉检查以经许可的固定样例和截图为证据。不能只用“生成了 PDF”代替排版验收。性能报告记录设备、系统、模型、网络与样本，区分本地处理耗时和 API 耗时。

## Git 与交付

- 主分支为 main；按明确目的提交。提交说明可用 `docs:`、`feat:`、`fix:`、`test:` 等前缀。
- 每次完成一项修改并运行相关检查后，立即创建独立的本地 commit；代码、文档、配置和格式修正均适用。交付时报告提交号。
- 不改写已有用户提交，不批量撤销用户修改。先查看差异，再暂存明确文件。
- 不提交真实阅读资料、聊天、Keychain 内容、签名证书、个人 Xcode 配置、构建产物。
- 当前的 Git 初始化只在本地；远程创建、推送、发布属于单独操作。
- 每次交付说明改了什么、验证了什么以及哪些尚未验证。环境无法执行的检查如实标记，不能用静态检查替代运行结论。
