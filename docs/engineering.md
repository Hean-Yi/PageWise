# 代码与工程规范

本规范约束日常开发、测试、文档同步与 Git 交付流程；当前实测结果见 [验证记录](mvp-status.md)。

---

## 1. 工具链与平台兼容

- **语言与平台**：Swift 6 语言模式、SwiftUI 与 Swift Package Manager；最低运行版本为 **macOS 15.0** / 暂定 **iPadOS 18.0**（开发基准 Xcode 26.2 / Swift 6.2.3）。新增系统 API 必须核对最低版本可用性，不得无意抬高 deployment target。
- **代码格式与命名**：使用工具链内置 `swift-format`（4 空格缩进，配置见 `.swift-format`）；类型/协议用 `UpperCamelCase`，属性/方法用 `lowerCamelCase`。用户可见报错需清晰易懂，诊断日志不得包含原文或密钥。
- **依赖管理**：引入新依赖前先核对许可证、维护状态与平台要求，提交 `Package.resolved` 锁定版本。

---

## 2. 分层与并发约定

- **依赖由外向内**：`App / Platform UI ──▶ Application Use Cases ──▶ Domain Models & Ports ◀── Infrastructure Adapters`。领域层禁止依赖 SwiftUI、PDFKit、WebKit、数据库或具体模型供应商。
- **状态与注入**：UI 状态用 `@Observable` 与 `@MainActor` 管理，View 不直接读写数据库或请求外部 API；网络、时钟、ID、文件与存储通过协议注入以便测试替换，避免不可替换的全局单例。
- **结构化并发**：CPU 密集解析（PDF/TeX/索引/向量）不阻塞主线程；跨隔离域数据严格满足 `Sendable`，禁止用 `@unchecked Sendable` 掩盖数据竞争。
- **任务与网络韧性**：
  - 长任务必须支持取消、进度报告、明确错误与持久化恢复点；前台问答优先于后台翻译与整理。
  - 网络配置超时、限流与有界退避，尊重 `Retry-After`；对 `401/403` 与无效参数不盲目重试，用户取消不视作故障。
  - 流式解析须处理网络分片与中断，仅保存通过本地校验的完整输出。

---

## 3. 持久化与安全不变量

- **显式迁移**：每次结构升级显式编号并附旧库迁移测试，禁止启动删库重建。
- **不可变与原子写入**：原始 PDF 与已发布重排页面不可原地修改；文件先写临时路径并校验，再原子提交数据库引用，启动时清理孤立临时文件。
- **密钥与内容隔离**：API 密钥仅存设备 Keychain，默认 HTTPS 且不跨域转发鉴权头；论文正文、网页、笔记与检索片段均视为不可信资料，不得覆盖系统指令或触发未授权操作。
- **HTML 与文件安全**：HTML 必须净化并本地化资源，禁用论文自带脚本；本地目录访问遵守系统授权与安全替换；Obsidian 写入须检测外部修改并保留用户手写区。
- **记忆保护**：用户修订不可被后台任务覆盖；删除记忆仅留最小墓碑与抑制指纹，不得复活已删除内容。

## 4. 测试与视觉验收门槛

核心逻辑使用 Swift Testing，平台交互与 UI 使用 XCTest / WebKit / AppKit 回归；不为纯文档或简单静态配置编写重复测试。

### 必须覆盖的关键回归
1. **页面与批注稳定**：追加翻译块后既有页面哈希与批注坐标不变，重启恢复一致。
2. **定位准确**：原页/重排页与语义锚点映射正确，公式与图表引用不串版。
3. **容错与去重**：中断、429、磁盘不足与残缺输出不发布损坏内容，重复导入/恢复不重复产出。
4. **问答与引用**：当前论文优先，引用来自真实检索证据，超预算时明确说明范围。
5. **记忆与笔记安全**：删除与用户修订不被覆盖，来源失效立即感知；Obsidian 重复导出不破坏手写区。
6. **统计与并发**：阅读日历重叠去重、跨午夜与补记准确；多实例写入受代次保护。

### 视觉检查与测试边界
- 默认自动化测试使用本地 fixture 与离线 Cassette / 假服务；真实模型联调需经用户明确授权。
- 视觉相关改动应构建 Mac 应用并在真实窗口中检查布局、排版与交互（测试结束及时退出并清理临时 `.app` 副本）；无法执行 GUI 验收时必须如实报告未完成视觉验收。
- 性能数据须标明设备、系统、冷暖启动与样本规模，区分本地耗时与网络模型耗时。

## 5. 文档维护与 Git 交付

### 文档维护（强制同步）
- **改动必留文档**：凡涉及功能增删、交互变化、架构调整、迁移升级或版本发布，必须在同一轮任务中同步更新 [README.md](../README.md) 及 `docs/` 对应文档。
- **保持目录整洁**：`docs/` 仅维护 7 份长期规范文档，不留存临时计划、分支实验记录或一次性草稿；采纳的实验结论应精炼归并到正式文档。
- **按主题维护**：直接修订对应章节，不以按日期追加的流水账形式堆叠；如实区分已实现能力、实测数据与后续规划。

### Git 与交付流程
- 主分支为 `main`，按目的使用清晰前缀（`feat:`、`fix:`、`perf:`、`docs:`、`test:` 等）。
- 每次完成修改并运行与影响范围匹配的检查后，立即创建独立本地 commit，仅暂存本次改动文件并在交付时报告提交号。
- 严禁提交真实论文库、聊天记录、Keychain 密钥、个人 Xcode 配置或构建产物；仅在用户明确要求时执行 `git push` 或打包 DMG。
- 交付时清晰列出**改了什么、验证了什么、以及哪些尚未验证**，不得声称未运行的检查通过。
