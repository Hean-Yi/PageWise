# PageWise 的研究记忆

这份设计回答三个不同的问题：「我收集了什么」「我实际追查过什么」「我目前认为或希望什么」。一次导入只回答第一个问题。研究方向要能回到几篇具体论文、几条讨论或笔记，读者也能纠正 Agent 对方向的归纳。

论文助读和书库助理共用读者明确表达的偏好。可以离线做词项检索，下载约 240 MB 的模型后也可以用中文寻找相关英文片段。下文记录本地实现及测试边界。原始基线和后续评测计划见[个性化对话与语义检索](personalized-memory.md)。

## 当前版本能做什么

| 读者的问题 | 现有数据与入口 | 能够确认的范围 |
| --- | --- | --- |
| 我在哪篇论文里记过这个观点？ | `search_reading_notes` 在设备上分块检索笔记正文，返回笔记 ID、可核对的摘录及论文。 | 可以用论文标题和笔记内容查找。检索会去掉正文中嵌入的引用标签。原文与锚点文字由独立的原文检索入口提供。 |
| 这篇论文具体说了什么？ | `search_library`、`read_paper` 和论文内问答读取已发布正文或可用原页。 | 引文须能定位。只有题注时只能讨论文字报告的内容。PDF 的可检索范围受本机已提取内容限制。 |
| 我研究了什么？ | `research_overview` 读取书架和由多篇题名、相关笔记形成的主题线索。按当前书架统计馆藏篇数、有未删除笔记（含 AI 批注）的论文数、有非精读讨论的论文数。未分类篇数单列，最多返回十二个有内容的书架。 | 同篇论文的十条笔记只计一篇。统计可反映投入。无参数时返回馆藏活动、主题线索及少量代表论文。提供 `query` 时可返回命中的笔记摘录，也可召回最多五条有来源、带用户修订或 AI 待核实标记的长期记忆。读者主动要求总体回顾时可传 `*`，抽取最多五条，用户修订优先，同等条件取较新条目。 |
| 它记得我的哪些关注点？ | 论文问答从读者原话抽取长期信号，用 `MemoryItem.sourceID` 追到对话。设置里的「研究记忆」可修改、删除及打开来源论文。论文问答按相关词、可选语义向量、用户修订及同篇来源筛选原记录，再按当前有效的归纳组装背景。 | 空提取、失败或引用其他阅读笔记的讨论都不会另存一份长期记忆。删除与更正会阻止相同命题再次自动入库；模型用完全不同的措辞表达同一含义时，还需下一阶段的语义冲突处理。 |
| 上次说到哪里？ | 书库 Agent 有按完整工具交换裁剪的短期会话，默认保留最近六轮。论文讨论则保存在对应论文里。 | 会话、个人研究记忆和文末阅读笔记是三种独立记录。书库提议用少量读者原话或来源笔记留证。短期完整会话与个人研究问题分别保存。 |

本版在设备上的 actor 中做词项和可选的向量检索。原文索引可在导入提交与重开书库后预热。已提交的 PDF 没有结构化正文时，可从可提取文字的原页建立缓存，按原文件内容哈希及页数校验。

新论文问答会记录本轮及从历史继承的来源，包括记忆的内容指纹和笔记的修订时间。续问只重用来源仍有效的轮次。记忆在生成途中被撤回时，应用停止采用该次结果；精读也在后续模型请求与保存前复核已读取的外篇笔记。书库助理清理依赖旧来源的上下文。读者仍可打开历史记录；缺少来源版本的旧问答默认不自动送回模型。

当前库保存用户已否决命题的规范化 SHA-256 指纹。删除论文后，相关正文与来源对话清除，只保留无正文、无来源 ID 的抑制指纹。旧版已经擦除且从未生成指纹的记录无法从空内容还原命题，只能沿用已有来源信息。

这次改动之前，论文问答直接装入最近八条记忆，模型决定不保存时仍可能把提问存成记忆。书库 Agent 能检索笔记，却没有研究活动概览。旧精读和读者手改的笔记沿用原记录。

精读、讨论和书库助理新写的笔记会随内容保存模型实际读过的背景版本，即使最后没有把某条来源写成链接。来源笔记改写、删除或长期记忆撤回后，依赖旧判断的笔记仍能在原位置查看、编辑、手动引用，Agent 的自动检索会排除它们。

早期精读与讨论报告只登记了部分引文。若引用的旧笔记、版本、原话和生成时间都能核对，应用可沿已登记引用恢复自动检索。缺少这些依据的旧 AI 笔记保留为手记；使用「重新精读」或让助读根据当前来源重新写笔记，可生成带有完整来源记录的新版本。没有报告、没有可辨别作者的旧条目会按普通本地手记处理。

## 空闲时怎样维护记忆

例如，读者在两次讨论中分别追问「蒸馏多花了多少算力」和「相同训练时间还领先吗」。所选 LLM 可以把它们整理为一个仍待验证的问题。下一次问实验设计，助理可直接找回这个共同关注点。输入偏好如「以后先讲直觉」会按书库、书架或论文范围单独提供。

每分钟检查一次空闲状态。应用已运行、至少两分钟没有读者活动、没有正在进行的对话或导入且设备未进入低电量模式时，自动处理已变化的来源。每批最多 20 条待处理记录、8 条同范围的既有记录，以及最多 12 条相关的既有归纳。每条来源最多发 400 字。队列仍有待处理项时约三分钟后继续，清空后约六小时例检；来源发生更改可提前检查。iPad 进入后台时中断，重新打开后从已提交版本继续。默认启用，可在「设置 → 研究记忆」关闭；模型服务按实际调用计费。

模型可以精炼自动记录、合并重复项、关联同题记忆、并列冲突、让后来明确改变的决定生效，也可以拆除以前建立的关联。其更改写入当前书库的 SQLite。正常对话直接读取最新有效版本，展开设置中的归纳可查看、修订或删除原记录。程序记录模型看到的整批来源，防止遗漏间接依赖。人工更正和明确偏好受保护。编辑或删除来源会使相关归纳失效；模型消息迟到或两个窗口同时整理时，主库代次与上一版检查会拒绝陈旧写入。缺少模型配置、网络失败或未产生有效更改时仍可使用既有记忆。

```text
new or changed records + prior edition
                    |
                    v
              idle LLM review
                    |
                    v
         source checks + atomic commit
                    |
                    v
           active research memory
                /          \
        paper chat      library agent
```

设计参考了 Anthropic 公开的异步 Dreams 工作流。PageWise 只向用户配置的模型发送选定记录与已有归纳，通过校验后直接激活，并在本机保留可追查的来源。[Anthropic Dreams](https://platform.claude.com/docs/en/managed-agents/dreams)

### 已实现的定期整理与自主写入

- 导入提交、笔记或讨论变化会触发设备端索引更新。前台运行约每六小时核对一次，重开应用时补查。SQLite 只在来源代次仍一致时发布派生索引；工作被打断后可从已提交的书库重建。无需网络或模型额度。
- 题名中的共同词项至少要在两篇独立论文中出现，才能成为跨论文线索。按具体主题询问时还可以汇集不同书架里的相关笔记，返回代表论文、可核对的摘录，以及笔记来源类型。每次最多返回四组主题。模型可据此提出解释或重新组合主题。书架、题名和纯 AI 批注只能说明材料与活动。
- 书库助理可以提议待追查的问题。来自书库对话的记录保留真实本轮的短引与轮次 ID，来自笔记的记录绑定笔记、论文及修订。新问题先标记为待核实。回顾已存研究问题走只读查询；明确要求别记时，书库提议和论文问答的附加记忆提取都会跳过。同时接触过其他私人来源时，新的持久记录只采用核对过的来源原话。读者可以在结果卡查看记录、修订或删除，修改会沿用设置里的同一套接口。

### 现有 Agent 工具

| 目的 | 实际工具名 | 权限与结果 |
| --- | --- | --- |
| 回顾研究与资料 | `research_overview`、`search_reading_notes`、`search_library`、`read_paper` | 概览、读者观点、论文原文分别查询。读取原页须先登记论文。 |
| 发现论文与交付结果 | `search_online`、`recommend_related`、`present_results`、`prepare_import`、`open_paper` | 下载与跳转生成可点击卡片。搜索失败和零结果分别报告。 |
| 精读与讨论 | `close_read_paper`、`create_reading_note`、`ask_user` | 精读、写笔记由本轮委托触发，引用须通过本地定位。 |
| 记录回答习惯 | `remember_preference` | 保存读者当轮明确表达的长期习惯及作用范围。一次性要求只影响本轮。 |
| 提议研究问题 | `propose_research_question` | 书库助理可以从本轮读者的原话，或已经检索并核实版本的读者手记，提出待追查的问题。应用核对原句、参与者、来源和重复记录；用户可在研究记忆中打开出处、修订或删除。 |
| 整理书库 | `list_library`、`prepare_local_import`、`create_shelf`、`rename_shelf`、`move_papers`、`prepare_delete_paper`、`prepare_delete_shelf` | 写操作按意图开放。永久删除论文需由读者在窗口确认。 |

共 21 个工具。每轮只开放当时可用的子集，默认工具预算为 16 轮、48 次调用。翻译、重排、导出到 Obsidian 继续走各自的任务入口。研究问题与明确偏好均可写入；后文列出的完整事件日志、跨设备协调和全库重置属于规划。

用同一张合成表格通过正式论文问答入口调用 DeepSeek，预设中文、预设英文和仅本轮用英文三次调用都保留了 A 组 61%、B 组 74% 和原文引用 [S1]。离线测试另核对当前书架、论文范围、临时覆盖和偏好撤回。条件性偏好目前按规则及原话中的关联词判断；真人长期对话的偏好识别质量尚待盲评。

## 自主研究记忆的目标模型

| 记录 | 作用域与身份 | 证据、所有权与失效 |
| --- | --- | --- |
| 来源 | 独立书库 ID、论文 ID、版式版本、块/页/笔记/对话 ID，加内容修订号 | 原始论文、读者手记、AI 批注、聊天中的明确表态分型。笔记写回原记录，索引只保存可重建的摘录。旧版可追溯，变更后摘录必须重新核对。 |
| 观察 | 来源 ID、修订号、用途、规范化主题、去重键 | 导入、首次有效阅读、用户笔记、讨论、手动更正各是一种观察。重复打开同一论文、同一次生成的多条 AI 批注按独立来源折叠。 |
| 记忆 | 稳定 ID、类型、作用域、用户可读的陈述、来源集合、状态、版本及最后验证时间 | 类型区分明确偏好、正在追踪的问题、研究方向假设和历史决策。记录谁陈述、谁归纳；用户修订生成受保护版本。竞争解释可并存。 |
| 研究简报 | 全局/项目/书架范围、主题 ID、版本、水位、证据引用 | 首页只读短摘要。展开可看来源、最近新增的材料、待检验问题及相反笔记。主题和书架多对多，移动书架只改归属。 |
| 更正与删除记录 | 记忆 ID、范围、不可逆关联标识、受影响的来源/主题及版本 | 删除清除可检索正文，留最少的抑制标记；删除后的回填、旧任务和跨设备合并均受抑制。真正的新证据可另作观察，不能自动重建被否定的用户立场。 |

### 增量索引与整理（已实现）

1. 论文导入、笔记编辑、讨论、移架和删除在主库事务内写入 `research_events`。事件只保存稳定记录 ID、内容修订哈希、所属论文/书架及书库代次，不保存笔记或记忆正文。事件键由事件类型、记录 ID 和修订哈希组成；同一次变更重试不会重复入队。
2. 每次研究来源变化同时推进独立的 `research_generation`。即使一条记录后来改回原先措辞、事件键被去重，代次仍会变化，派生索引按新代次重新核对，不会停在中间版本。阅读位置、工作区和翻译保存不生成事件，也不推进研究代次。
3. 前台空闲时按最多 256 条待处理事件处理；一批完成后若仍有待处理事件，继续处理直到水位追上，而不是等待下一次定时核对。`research_index_state` 保存已覆盖的研究代次、最后事件序号和最近核对时间；`research_maintenance_lease` 保证同一本地库同时只有一个带到期时间的整理任务；长任务在预热和发布前续租，失败按 15 秒起、最长 5 分钟退避。已处理事件保留最近 4,096 条，未处理事件不裁剪。Mac 与 iPad 各自运行；重开应用后从未覆盖的代次继续。
4. 派生简报与水位在同一条 SQLite 事务中发布，并校验发布时的研究代次、书库代次和上一版载荷。模型或索引中途遇到新来源、陈旧任务或取消时不推进水位；已提交的事件可在下次重放。删除 `research_brief`/`research_index_state` 后，应用会从主库重建，而不是把派生数据当权威。
5. 当前仍由设备端题名词项索引生成简报；按主题 ID、版本和证据引用组织的模型简报，以及 `propose_memory`/`revise_memory`/`forget_memory` 完整工具面，仍按后文的目标模型推进。模型综合继续由空闲整理会话处理，无网、无钥匙或失败时保留已有索引。

### 何时把一个主题称为研究方向

每条推断拟保存独立的支持证据和反面证据。候选只在有可核对来源时进入「待核实」。读者主动认可后进入「已确认」，新材料出现冲突时并列记录判断及适用条件。长期未出现的自动推断可从简报淡出，仍能追溯；读者主动删除的条目进入抑制清单。待核实、已确认和已删除三种状态只能通过带当前版本的变更更新。一次模型返回不得同时充当提议者与确认者。

- 一篇新下载的论文只算「已收藏的材料」。同篇打开十次或一次精读十条批注仍是一篇，不能把次数当独立支持。
- 有两个独立论文来源，且至少一处含用户撰写/实质修改的笔记或明确追问，才可创建可见的「可能在追踪」。这是拟采用的保守初值，要用真实授权样本校准。纯 AI 批注不能当作读者认同。
- 明确的「我在研究……」「今后请优先……」可直接保存为有来源的自述，优先于系统推断。方向变更按时间保留历史，不把新旧观点拼接成同一个事实。临时任务和仅作为假设举出的立场不提升为偏好。
- 例如两篇蒸馏论文都有关于「等计算预算」的读者笔记，可以说「你多次关注比较是否控制计算量」，并给出两条笔记。若只有书架中有这两篇，只能说「书库收录了相关论文」。

### Agent 自主管理与读者控制

| 设计中的操作 | 自动管理范围 | 必须交还给读者的动作 |
| --- | --- | --- |
| 检索与概览 | 按问题和论文/书架范围取少量活跃记忆，支持主题与原词混合召回，返回出处和记录版本。泛化问题才用同一书库内跨书架的概览。 | 设置可查看哪些数据参与以及最近一次使用。可暂停本轮或全库读写。 |
| 提议与合并 | `propose_memory` 提交类型、范围和已登记的来源；程序复核后才允许新增推断；现有 `propose_research_question` 是这一机制已经上线的窄接口。相同来源版本幂等去重。自动内容可更新或合并，并保留来源链。 | 覆盖用户编辑、把推断升级为用户自述、合并相互矛盾的观点需明确确认。 |
| 更正与遗忘 | `revise_memory` 使用期望版本，`forget_memory` 按用户明确的对象和范围执行。所有操作有本地审计记录。 | 含糊的「忘掉那个」先展示候选。重置整库或删除论文继续由窗口确认。支持查看来源、修改、删除、暂停。 |
| 周期梳理 | 识别重复主题、失效引用、尚未解决的问题和相反证据；只更新可推断层。 | 不修改原笔记、书架或 Obsidian 文件。Obsidian 继续由用户主动导出。 |

检索先按范围、权限、删除标记和源版本过滤，再做中英文词项及别名匹配，综合直接关联、独立来源数、用户修订和时效排序。读者问「我以前怎么想」优先找手记，问「论文证明了什么」回到本篇可定位证据，要求找新论文就走在线检索。弱相关时返回空。当前研究简报已有可重建的本地索引；事件日志已提供来源级增量，块级来源关系和阅读观察仍待扩展。向量记录沿用同一套来源、失效和删除规则。

### 验收与上线顺序

下面是拟落地的数据流。主库保存读者资料；即使派生索引被清空，仍能按来源重建。

```text
library transaction -> event log -> local index -> scoped retrieval
                           |                            |
                           v                            v
                     idle review -> sourced brief -> agent context
user edit / delete -> revoke source revision -> invalidate dependents
```

例如读者把「我长期关注样本效率」修订为「我现在只追查等算力下的比较」。新的提问会取修订后的原话；依赖旧表述的简报应立即隐藏相应判断。下一次整理读取仍有效的讨论和手记，只更新受影响的主题。旧设备重连或上一次推理稍后返回时，提交必须先核对修订号。读者自己写的历史笔记仍可在原位置打开。在共享书架中看到相似词汇，不能撤销这次修正。

模型处理的正文、引文及记忆都作为资料输入。权限由本轮操作和来源范围决定，论文中出现的指令不能触发改架、删除、模型调用或写入个人偏好。每次自动写入需保留来源 ID、修订、触发事件和变更类型，设置中可据此解释一条记忆为什么出现。默认诊断只保留计数和错误类别。

1. **事件与可重建索引。** 用批量导入、重复导入、崩溃重开、移架、删文档、两任务并发和旧版库升级验收。核对待处理事件完成后的条目数、水位、重复/悬空记录数及磁盘占用。
2. **研究简报与 Agent 维护工具。** 用已知书架和人工标记的中英混合问题验收。分别评测笔记命中率、错误归因、无答案时克制、来源能否打开、删改多久反映到新请求。用匹配数、主题准确度及交互延迟分别评估。
3. **隐私控制与恢复。** 验证暂停前后、新设备、无网、低电量、取消、撰写中删除来源、模型返回陈旧数据、混入文档指令和相互矛盾的笔记。删除复活、模型覆盖用户更正、无来源表态，任一出现都不能发布自动写入。
4. 用同一组真实授权问题比较「最近若干条」「本地词项召回」和新的主题检索。分开统计前五条中能直接回答问题的比例、不该召回时出现私人材料的次数，以及冷启动、热查询的 P95。对删改、归因及恢复用固定样本做发布门槛，性能门槛则按最低支持设备的实测基线制定。
5. 本地只记录时延、数量和失败类别。诊断和同步数据均不得包含密钥。跨设备同步若启用，手动更正和删除优先，冲突保存可追溯版本。每台设备独立重建索引。设备端调度和模型接入分开，均可单独关闭。

Claude 公开说明了分项目记忆、可编辑主题、暂停、删除及周期更新。PageWise 的后续设计借鉴这些用户控制，并增加论文、阅读版本和引文级溯源。其公开帮助描述的是产品行为。[Claude 的记忆与历史检索](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)

开源 LangMem 把会话中主动管理与后台提取、合并分开。下一阶段拟保留 Swift 设备端实现并采用这种任务划分，把人工修订与来源版本校验放在提交事务内。[LangMem 源码](https://github.com/langchain-ai/langmem) · [LangMem 设计说明](https://langchain-ai.github.io/langmem/concepts/conceptual_guide/)
