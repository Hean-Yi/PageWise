# 让 PageWise 记得读者怎样做研究

**设计提案，基线为 v0.3.0。** 读者在论文助读里说过「以后看实验先告诉我对照是否公平」，下周打开书库助理问「这篇值得细读吗」，这句话也应该起作用。它改变的是 Agent 先讲什么、找哪类依据。论文结论的强弱仍取决于能定位的原文。这份提案同时设计日常对话的个性化与设备端中英向量检索。

## 从一次对话看效果

以下是用虚构表格写的验收样例。给三个会话同一份材料，只说明方法在相同训练时间下得分更高，未给出样本量。三个读者都问「这个结果说明什么？」

| 此前留下的记忆 | 期待的回答开头 |
| --- | --- |
| 没有相关记忆 | 「在同样的训练时间内，新方法得分更高。表里没有各组使用的样本数。」 |
| 「以后看实验，先说对照是否公平」 | 「训练时长对齐了，样本量还核对不了。所以这张表支持等时间下表现更好；要判断是否更省数据，还需要等样本量的对照。」 |
| 「我刚接触这个方向，先讲直觉，术语附英文」 | 「可以把它想成给两个选手同样长的考试时间，其中一位得分更高。我们还不知道他练了多少题，所以暂时判断不了样本效率（sample efficiency）。」 |

同一读者临时说「这次我做组会，给英文一句话」，当轮按这个要求回答，下次继续用原来的习惯。问「你为什么先谈训练预算」时，Agent 可以展示本轮选入的偏好及其出处，读者可直接更正。

## 两个对话入口，共用一套记忆

0.3.0 的论文助读已能从读者原话提取长期计划、偏好和问题，但召回依赖词项相关度。书库助理可以通过 `research_overview` 读取记忆，主动写入工具目前仅接收待查研究问题。`MemoryItem` 有来源、手动修订和删除信息，缺少明确的适用条件与有效期。[论文助读](../Sources/PaperReaderUI/Application/Assistant/AssistantActions.swift) · [书库助理](../Sources/PaperReaderUI/Features/Agent/LibraryAgent.swift) · [现有记录结构](../Sources/PaperReaderKit/Domain/Assistant/MemoryItem.swift)

建议在两个入口组装首个模型请求前，共用一个本地的上下文组装步骤。Agent 可以继续选择是否扩大检索，从事日常问答时无需先调用一次工具来认识读者。

| 对话需要的资料 | 来源与触发 | 在回答里的用途 |
| --- | --- | --- |
| 长期表达偏好、工作习惯 | 用户明示的语言、术语、深浅、反馈方式；按当前任务选取适用项。一般性的「先讲结论」可以跨主题使用。 | 调整表述和顺序。「读实验时给出分母」仅适用于有实验的任务。要求下载论文时仍直接走在线检索。 |
| 个人背景与项目决定 | 用户自述的已有知识、当前工作、项目约定，记录生效范围与时间。例如「这次综述把样本效率定义为等数据量下的表现」。 | 选择解释起点，沿用特定项目的约定。离开该书架或结束该项目后，其他任务使用各自的定义。 |
| 研究兴趣、待查问题、过去的讨论与判断 | 按当前问题用词项与向量找相关的手记、已核实的对话摘录、研究方向或决定。作者及时间跟随结果。 | 帮读者接上思路，如「你之前在另一篇笔记里也追问过训练预算」。历史推测保持原来的归属和不确定性。 |
| 论文事实与数据 | 当前选区、上下文、表格文字或可定位的原页；按需回查本地其他论文。 | 支撑学术主张。用户记得一个数字或喜欢某个方法，仍须用论文证据核对。 |

会话临时状态随会话结束而释放。全局指同一独立书库中的两个 Agent。每条长期记录携带用途、自由文本、可选偏好项、范围（书库、书架或论文）、状态、有效时间、来源角色、来源 ID/修订及本条修订。通用偏好项用于处理「以后用中文」与「改用英文」之类的冲突。Agent 可自行提出新主题、措辞和适用条件，界面无需让读者填画像问卷。

已明确的偏好可以在事实类问答、闲聊与工具结果说明中自然生效；例如问「什么是置信区间」也会沿用读者约定的解释深度。个性化可以改变呈现方式、例子和主动追问，不能为了迎合读者而改变数值、隐藏不利证据，或虚构一段“你以前说过”的经历。

## 回答前如何取回材料

```text
reader turn + selection + active scope
    |-- applicable preferences -------------------------> response style
    |-- lexical + vector search -> notes and memories --> personal context
    |-- pinned passage + paper search ------------------> citable evidence
    +-- current request + verified sources -------------> answer
```

1. 首先执行当轮指令与记忆范围控制。读者说「这次别用我的记忆」时，对应历史轮次里派生出的个人信息也跳过。「这段别记」允许完成本轮问答，关闭本轮长期写入和以后从这轮自动提取。当前明确要求优先于长期习惯，更具体的适用范围优先于全库默认；同一范围内采用最新有效的用户更正。
2. 直接读取少量适用的明确偏好。条件性偏好、旧决定和相近的笔记走混合检索。先按书库、用途、来源版本、删除状态和时间过滤，再在各类资料内分别取词项与向量候选。用带有无答案样本的开发集，按资料类型和编码版本校准各通道的入选门槛。仅对达标候选做倒数排名融合（RRF），按来源去重，保留不同观点，再核对实际摘录。两个通道都没有合格项就返回空。用原词保住 `OPSD`、DOI 和公式编号，用向量找出「两组用了相等的资源吗」与 “matched compute budget”。相似度只产生候选，不能证明两条记忆同义，更不能裁决相反意见。
3. 首轮建议预算为个人背景约 600 tokens，优先容纳适用的明确偏好，再选最多三条有帮助的历史片段。当前论文证据沿用独立预算，选区及邻段优先。有多个相互冲突且未经确认的习惯时，本轮采用中性表达；只有差异会实质影响结果时才请读者选择。空命中或向量超时都可以直接回答。
4. 模型分别收到「回答偏好」「个人研究背景」「可引用证据」。生成与写回前复核实际送入的来源版本，继承记录接入现有 `ChatSourceVersions`。每轮回执只记实际提供过的记忆 ID、修订和选择用途。询问原因时，可报告「本轮提供了这条实验阅读偏好」，或指出程序确实应用的语言或格式设置；模型看到某条背景不足以证明它造成了某一句回答。已撤回的正文不能从回执还原。只有证据才能生成论文引文。读者对话中的授权决定工具权限，论文、导入的片段和历史笔记中的文字不能授予权限。联网查文章时仅使用必要的论文主题或书目词，个人偏好留在本地组装或已选对话模型的最小上下文内。[来源版本检查](../Sources/PaperReaderKit/Domain/Assistant/ChatSourceVersions.swift)

## Agent 怎样学会、改口与忘记

| 读者的表达或活动 | 建议的行为 |
| --- | --- |
| 「以后默认用中文，术语保留英文」 | 两个对话入口都可以提议写入。有可核对的当轮原话、持续意图和作用范围即可生效，一次低干扰回执支持撤销。 |
| 「这次只讲直觉」或引用另一位读者的话 | 前者留在本轮，后者保留说话者身份。后台整理也沿用这一归属。 |
| 在不同讨论里，读者多次追问同类实验对照 | Agent 可关联独立的读者发言，提议「可能经常关注对照条件」并保留依据。低风险时可优先补充一项核对；涉及读者立场时只作为待查线索。重复打开论文、AI 自己写的批注、Agent 已经用过某条记忆，都不增加支持度。 |
| 「以后简短一些」接着「这一节详细推导」 | 前者可调整长期偏好，后者仅覆盖这一节。出现永久更正时替代旧版；两种说法适用于不同场景时保留条件。 |
| 「忘掉我偏好短回答」 | 若范围和对象唯一，沿用现有删除流程；含糊时只展示候选。下次请求立即停止使用，被撤回的内容从摘要、向量、热缓存和可自动回放的历史中失效。 |

写入复用现有持久化入口，将 `propose_research_question` 保留为兼容入口，转交相同的带类型提议处理。Agent 可选择新增、关联、细化范围、建议替代或跳过。程序核验来源作者、原句、范围、期望修订和去重键，禁止后台修改读者手工修订。保存偏好只需引用必要的读者原话，避免把同轮见过的其他私人笔记一起保存。原话涉及账号凭据或与工作无关的敏感信息时跳过自动提取。已知个人风格不能授权下载、删除论文或自动导出 Obsidian。

删除时在主库事务内使记录失效并登记最少的抑制信息，再清理派生数据。写入和索引任务提交时均检查来源修订与删除代次。对于明确偏好，用同一范围和偏好项屏蔽旧来源重新推断；开放文本沿用指纹并阻止从已撤回的来源重提。新出现、措辞不同而疑似指向已撤回偏好的线索保持未激活，用户新的明确表态可以重新建立。相似度无法保证识别所有改写，避免为「遗忘」再留一份可检索的旧正文或旧向量。原始手记仍由读者管理。

日常整理沿用当前前台约六小时核对、重启补查的时机。先处理有变化的来源，合并重复候选、标出冲突、淡出过期项目；保留手动修订和决定的生效时间。读者在现有设置中即可查看、编辑、删除，也可在任一对话里问「你记得我哪些偏好」「这次用了哪条」，查询本身保持只读。

普通聊天复用当次对话产生的记忆提议，写入成功后才显示回执。纯问候与没有新增信息的轮次直接结束。定时维护只做设备内的索引和状态核对；需要模型判断的合并建议留到有相关上下文的对话，避免静默重发历史或为每轮额外支付一次模型费用。

## 本地向量检索的技术选择

首个候选是 MIT 许可的 `multilingual-e5-small`。它输出 384 维向量，输入上限为 512 tokens，查询与段落采用各自的前缀，按掩码做平均池化并归一化。上游单份权重约 471 MB，建议将转换后的模型作为按需下载的独立资源，下载前显示实际大小，模型包固定版本、许可证及校验值。Mac 与 iPad 都在设备上编码；现有 DeepSeek 等聊天服务继续处理回答。Core ML 转换后须核对中英分词、相似度排序、体积和实机性能。[E5 模型卡](https://huggingface.co/intfloat/multilingual-e5-small) · [权重文件](https://huggingface.co/intfloat/multilingual-e5-small/tree/main) · [Apple 转换指南](https://apple.github.io/coremltools/docs-guides/source/convert-pytorch.html)

建议首版沿用 SQLite，将向量写入可删除重建的派生表。在已限定的集合内分批读取，利用 Accelerate 对归一化向量做精确点积，作为质量和速度基线。384 维 Float32 向量每条 1,536 字节，一万条的向量本体约 14.6 MiB，另计模型、元数据和数据库开销。大书库实测出现瓶颈后再比较静态集成 `sqlite-vec` 的查询、内存与迁移成本。上游仍标为 pre-v1；这一决策可在同一检索接口后替换。[sqlite-vec 源码](https://github.com/asg017/sqlite-vec)

由现有导入提交、发表重排块、修改笔记与记忆修订事件产生待处理记录。首批覆盖偏好、读者笔记与项目决定，随后覆盖论文摘要及正文。按语义段落或笔记标题分块，必要时按 tokenizer 上限再分，保留稳定的原文锚点。派生记录按书库、来源类别、来源 ID、修订、块键和编码版本唯一；编码版本包含模型、分词器及分块规则。异步队列可取消、去重、断点恢复。新版本在旁路重建，核对来源代次后原子切换；禁止不同模型空间相互比较。在模型未安装、离线且资源缺失、索引未覆盖或设备忙时，原有词项检索及明确偏好仍可用。后台仅发送模型下载请求所需的信息，生成 embedding 在本机完成。

## 交付顺序与验收

1. **先让一般对话用得到记忆。** 两个 Agent 共用适用偏好读取和提议入口，扩展现有记录与迁移。旧记录保留 ID、来源、更正和删除状态；缺乏明确证据的旧项保持原归属和未分类状态。离线用固定响应模型核对组装的上下文和实际写入。成对对话对比空记忆、两种不同偏好和一次性覆盖，检查表达确实不同，原文数字、引用与证据强弱一致。
2. **再验证向量带来的增益。** 用有人工标注的中英查询比较词项、纯向量、混合三组，固定同一书库、权限、锚点与候选预算。分别报告跨语言改写、缩写、否定、无答案和跨项目干扰的 Recall@5、首个正确结果排名与误召回率。拟定发布门槛为跨语言改写组的 Recall@5 比词项基线高至少 10 个百分点，精确编号固定用例全数命中，越域或被撤回材料进入模型为零。预留独立评测集，避免用调参样本报成绩。
3. **最后打开自动归纳并评测真实回答。** 用原创或获授权的多轮样本覆盖偏好建立、暂时例外、更正、删除、重开、两个写入并发、索引中途换版及生成中撤回。固定样本出现一次擅自覆盖手改、泄露被撤回信息、把作者观点说成用户立场，均阻止启用。另做盲评，检查个性化是否有帮助、是否牺牲证据、是否频繁提起无关旧事。在 Apple 芯片、Intel Mac 与最低支持范围内的 iPad 实测查询 P95、首个回答前增加的等待、峰值内存、建索引耗时及模型体积，再决定是否默认启用。以上指标是验收目标。[LongMemEval 的多会话更新、时序与无答案评测](https://github.com/xiaowu0162/LongMemEval)
