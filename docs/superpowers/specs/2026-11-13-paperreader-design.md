# PaperReader 设计草案

日期：2026-11-13。状态：待用户评审；未开始应用实现。

产品承诺以 [需求基线](../../requirements.md) 为准；推荐技术及来源见 [技术选型](../../technology.md)，代码规范见 [工程约定](../../engineering.md)。本文将用户已经确定的行为转化为可验证的模块和数据契约，原型验证项不视为已实现。

## 1. 目标与交付边界

构建本地优先的 Mac / iPad 原生应用，支持论文发现、逐段双语阅读、页面内自由手写、基于来源的问答、自动长期记忆、手动保存到 Obsidian 和阅读日历。

最低 macOS 15；iPadOS 18 为暂定基线。两端拥有完整本地处理能力，用户无需运行服务器，也无需保持 Mac 在线供 iPad 使用。在线模型依赖用户的 GLM 配置。

第一阶段不含云同步时，应用必须清楚显示“仅保存在此设备”，不能暗示数据已经跨设备备份。会员可用后完成 CloudKit 和朋友分发，才达到完整多端版本的验收。

## 2. 主要界面

Mac 使用书库侧栏、阅读区及可收起的 AI / 笔记面板。iPad 使用同一导航模型，侧栏和讨论面板可收起，为阅读与 Pencil 留出空间。

导航包含书库、阅读日历、记忆、任务与设置。论文详情展示来源、版本、处理状态、阅读进度、笔记链接和固定版式版本。

阅读器提供双语页与原始 PDF 切换、目录、文字选择、高亮、手写工具和问答入口。原始 PDF 与重排页是同一论文的不同视图，但其坐标独立；仅在已验证的语义锚点之间跳转，不能把原始页笔迹直接贴到重排页。

首次生成页面前可以预览并调整字号、页宽和留白。首个页面发布后，该版式版本的设置冻结；以后换字号会创建新的版式版本，旧版和批注保留。两端以缩放显示同一页面，不通过改变窗口宽度重新排版。

## 3. 模块与依赖

```text
SwiftUI App
|-- Library / Import
|-- Reader / Annotations
|-- Assistant / Memory
|-- Notes / Calendar
`-- Settings / Jobs
          |
          v
Application Use Cases
          |
          v
Domain Models + Service Ports
          ^
          |
Adapters
|-- arXiv / PDF / HTML parsing
|-- GLM / compatible model transport
|-- Typesetter / PDFKit / PencilKit
|-- SQLite / asset store / Keychain
|-- Obsidian directory access
`-- CloudKit sync (later)
```

- Discovery：接收查询，返回带来源的候选与匹配依据；只负责身份与下载来源，不负责排版。
- Ingestion：接收来源文件，输出 DocumentIR、源锚点和质量报告；不直接写 UI 状态。
- Translation：按语义块翻译、保护公式和引用、缓存完整结果；输出可校验的双语块。
- Pagination：将连续完成的块生成固定页面与几何索引；没有修改已发布页的接口。
- Annotation：存储文字范围、笔迹和修订，不修改基础页面。
- Retrieval / Assistant：构建有证据的上下文和回答；不直接修改笔记或执行来源中的命令。
- Memory：根据记录更新有来源的长期记忆，保留用户纠正和删除优先级。
- Obsidian：授权目录读取、笔记映射和用户触发的安全写入。
- Activity：产生不可变阅读事件，计算日历与修正后的视图。
- Persistence / Sync：维护事务、附件、恢复点与同步队列；无云服务时用例仍可完成。

## 4. 导入与处理流程

```text
Title / PDF
    |
    v
Resolve identity ---- ambiguous ----> User selects candidate
    |
    v
Download + verify + retain original
    |
    v
Version-matched HTML / local PDF analysis
    |
    v
DocumentIR + quality report
    |                        |
    | reliable               | unreliable
    v                        v
Translate ordered blocks    Original PDF reader
    |
    v
Draft page -> validate -> publish immutable page -> append
```

明确匹配要求规范化标题唯一命中，标识符与版本无冲突；模型置信度不能替代来源验证。重复的相同标识符/版本或文件哈希指向已有论文，不重新下载或重复消耗翻译。

首个适配来源为 arXiv；本地 PDF 是同等级入口。下载验证类型、完整性和内容哈希；错误页不能作为 PDF 入库。HTML 与 PDF 版本不一致时不混合内容，转入用户确认或 PDF 路径。

DocumentIR 包含标题层级、段落、公式、图表、代码、引用和源顺序。块拥有稳定 blockID、源内容哈希、原始来源定位以及可能的 PDF 页面/矩形。公式不通过语言模型重写来“修复”；图表和公式没有可靠结构时保留可定位的原图资源。

质量检查分为提取质量、译文结构完整性、页面几何完整性：检查顺序、块数量及标识、资源存在、公式占位符、缺失译文、字符/资源越界和剪裁。自动检查不能证明所有论文语义无损，UI 始终提供查看原文和报告排版问题的入口。

如果转换在中途失败，停止发布新重排页、展示原因并打开普通 PDF。已有固定页及笔迹保留为当前版式记录，不删除用户工作；未通过检查的页面不展示为正常译文。

## 5. 渐进翻译与不可变页面契约

本地先建立文档结构、资源和排版模板；未知译文只存在于待处理区，不占据正式可批注页面。翻译可有限并发，页面仅发布连续完成的前缀，避免后来补齐前文造成插页。

```text
Block 1 translated --+
Block 2 translated --+--> Page A draft --> sealed A --> readable + ink
Block 3 pending ----+                         |
                                             | unchanged
Block 3 translated ----> Page B draft --> sealed B --> append
```

发布规则：

1. 英文及对应完整译文均已校验，相关图片和字体已就绪；不将 token 流中的半句当作稳定排版内容。
2. 通过受控 HTML 模板排版并显式分页；记录文字范围、段落和公式/图表几何位置。WebKit PDF 导出只负责输出，不假设其自动满足论文分页要求。
3. 页面达到容量或首屏所需内容已准备好，即可封存；为了早显示而提前封存产生的留白不再回填。
4. 同一英文/中文段落对尽量同页；超长块使用带相同 blockID 和字符范围的续页。图表与图注共同布局，超大图表使用专页或明确的原图放大入口，不能缩到无法辨认。
5. 页面文件、几何映射和资源哈希完整落盘后，事务提交 PageArtifact，阅读器才能显示。
6. 已发布页面的字形、行距、尺寸、内容和编号不变；其他设备下载相同制品，不能重新渲染冒充同一页。

版式内的正文保留可选择文字，另有语义索引；不能为方便批注把整个正文栅格化成图片。字体或数学渲染不能满足这一要求时，必须调整渲染路线或退回 PDF。

译文修正、字体调整、提示模板升级及新版本论文均产生新 revision。旧页面和笔迹仍可访问；自动迁移笔迹不是第一版承诺。缺页或附件未同步完成时显示加载状态，不能用临时重排内容占用已固定页面的身份。

## 6. 手写和选文定位

笔迹绑定 `(paperVersionID, layoutRevisionID, pageID, pageDigest)`。几何位置使用页面坐标，不保存视窗像素；缩放、滚动和旋转只改变显示变换。

iPad 使用 PencilKit 保存原始可编辑笔迹，另外生成适合 Mac 展示及笔记导出的预览。Mac 不要求复刻 Pencil 工具输入，但必须能查看、定位已有批注，以及完成键鼠文字选择、高亮和问答。

文字批注记录 blockID、原文/译文标识、字符范围及页面矩形，引用同时带内容哈希。公式与图表可通过语义对象或框选区域提问；非文本内容需要视觉能力时，发送用户选中的区域及上下文。当前模型不支持视觉则明确说明，并提供图注/相关正文解释，不能假称看到了图片。

笔迹默认以图像附入 Obsidian，不自动假定已准确识别其中的文字和公式。

## 7. 问答与 RAG

```text
Selection + question
          |
          v
Current paper: local context + structure + relevant full-text blocks
          |
          +--> Optional supporting evidence: library + allowed notes
          |
          +--> User memory: explain at the right background level
          v
Budgeted context -> GLM -> validated source links + answer
```

当前论文先形成完整索引，再按问题检索其各章节；选中内容及相邻段落必入上下文。全文在预算内时可直接提供全文；超过预算时使用结构信息及相关片段并标明检索范围，不能声称模型逐字阅读了整篇。

默认上下文打包先保证当前论文证据，外部论文和笔记不得将其挤出。回答先解释本论文，再在有帮助时补充其他来源。Memory 调整解释深度与术语，不作为学术事实证据。

第一阶段为本地 FTS5 + 中英文分词、查询改写和结构化扩展检索；所有引用必须来自实际加入上下文的 SourceAnchor，并由应用验证。没有足够证据时直接说明缺口。用户指定的 Obsidian 范围之外不索引。

模型能力按配置检查；Key 仅在设备 Keychain。翻译、问答与记忆任务共享服务但分离提示模板、优先级和上下文预算。API 已返回的 usage 可用于记录调用量；价格未知时不编造费用。

## 8. Memory 生命周期

记忆分为研究兴趣、知识背景、论文理解/进展和开放问题。对话结束或阅读会话结束后，将已持久化的新记录加入去重提取队列；在应用运行且高优先任务允许时自动整理，不要求额外确认。

每条记忆记录来源 ID、提取依据、适用范围、事实/推测标记、创建/更新时间和修订关系。阅读进度来自事件；“用户不懂某概念”不能由一次提问直接当作确定事实。

用户编辑优先于自动提取。自动推断互相矛盾时保留修订与冲突状态，不能静默改写用户明确背景。删除时删除正文，保存最小墓碑和来源抑制标识，避免原始聊天再次产生同一条记忆；新来源提出相关内容时也要尊重该抑制范围。

来源被删除或版本变化后，派生记忆标为失效并重新评估；派生记忆不是永久正确的个人画像。失败不会丢失对话，不阻塞阅读，队列支持恢复。

## 9. Obsidian 笔记契约

每台设备通过系统选择器选择笔记库及允许索引的子目录。授权信息留在设备，不作为其他设备可复用路径同步。

使用稳定 paperID 关联一篇论文的一份 Markdown 笔记；标题用于文件可读名称，paperID 保证改名后可识别。论文不同版本属于同一笔记中的明确版本记录，不偷偷混合引用。

笔记包含论文元数据、阅读记录、批注附件、总结、可选讨论整理和用户自写区域。文件内用带 paperID / blockID 的标记划定应用管理区，并保存上次写入的哈希。用户可在管理区之外任意编辑；若管理区也被用户改动，展示差异选择，不能默认覆盖。

保存过程：

```text
Save to Obsidian
    |
    v
Ask whether to summarize discussion
    |
    v
Prepare selected content + source references + ink attachments
    |
    v
Read latest file + compare prior baseline
    |                       |
    | no conflict           | conflict
    v                       v
Coordinated write        Review changes / save separate copy / cancel
```

“否”仅表示本次不新增/更新讨论整理，不删除过去已经保存的讨论。讨论整理记录范围和对话 ID，重复保存不会重复追加。用户区按原字节保留；损坏或重复标记不能由模型猜测修补。

手写附件使用稳定 ID 和哈希，先保存附件再更新引用；最后一步失败不会破坏旧笔记。iCloud 延迟、文件被移走、尚未下载、权限撤销或外部编辑均显示明确状态。并发编辑采用文件协调及基线比较，仍保留可恢复的旧版本；对跨设备提供方冲突需额外检测，不把一次本地原子写入当作全局事务。

## 10. 日历与阅读事件

记录 sessionID、paperID、deviceID、时间区间、所在时区、相关活动和手动修订。页面可见且应用前台时开启估计阅读；后台暂停。长时间无操作采用可配置阈值，默认建议 5 分钟后暂停计时并允许用户补记，避免声称能准确判断人是否正在阅读。

原始事件不可变，人工补记/修正产生新的事件。日历按用户选择的显示时区切分跨午夜区间；同一论文在多设备重叠的区间取并集，全天总时长也按时间区间去重。每日列表显示论文、估计时长、批注数和笔记活动。

## 11. 核心数据模型

```text
Paper
|-- PaperVersion
|   |-- SourceAsset
|   |-- DocumentBlock + SourceAnchor
|   |-- TranslationRevision
|   `-- LayoutRevision
|       `-- PageArtifact
|           `-- AnnotationRevision
|-- Conversation -> Message -> Citation
|-- ReadingEvent
`-- ObsidianNoteBinding

MemoryItem -> MemoryRevision -> SourceReference
ProcessingJob -> Checkpoint
LocalMutation -> SyncOutbox
Deletion -> Tombstone
```

PDF、图像、页面和笔迹是文件制品；数据库保存 ID、修订、哈希和引用。检索索引、缩略图与缓存均可重建。没有同步的设备仍完整保存本地事实和恢复状态。

## 12. 同步、恢复与冲突

正式方案使用 CloudKit 私有数据库同步记录及附件。设备上的 SQLite 保持本地，不通过文件同步直接共享。API Key、目录书签和本地缓存不进入同步内容。

不可变页面按内容哈希验证；在页面和依赖附件齐全前，不标记为可离线阅读。手写保存为带父修订的版本；离线同时修改同一批注产生分支，保留双方并让用户选择或合并，不静默丢弃一方。

两台设备同时处理同一论文可能生成不同翻译与版式：同一已发布版式采用单一生产者身份，另一端接续前必须确认完整检查点。离线时另起版式分支，联网后展示选择；不能把不同页面混入同一 revision。来源与输入哈希相同也不保证模型生成字节相同。

元数据合并以明确字段规则处理；阅读事件按 ID 去重；聊天按会话和消息 ID 保留；记忆按来源与用户修订优先级合并；删除使用墓碑传播。退出或更换 iCloud 账户时暂停原同步队列，数据按账户隔离，未经用户选择不得把旧账户资料上传到新账户。

本地处理任务以语义块/页面为恢复边界。任务状态包含 queued、running、paused、failed、completed 和原因；切到后台时尽力保存，启动时也能识别上次意外中断。401、429、断网、磁盘不足、资源缺失分别显示处理办法，已完成内容仍可读。

## 13. 实施阶段与验收

### D0：当前设计交付

建立本地 Git、需求基线、技术对比、规范和本设计。自查范围与矛盾后交用户评审；当前未创建应用骨架。

### P0：可行性原型，先验证再扩展

1. 双端固定页面：使用带正文、长公式、宽表格、图注和代码的合成文档，在 Mac / iPad 输出并显示固定页。验证正文可选择、锚点准确、后续追加不改旧页；失败则改用原生排版适配器。
2. iPad Pencil：在同页圈词和跨行画箭头，缩放、翻页、重启、在 Mac 展示后位置仍正确；保留可编辑笔迹及预览。
3. Obsidian：用户授权的真实测试目录中验证读写、重复保存、用户编辑保留、改名、权限撤销、离线文件和写入中断；不得使用实际个人笔记作为自动化 fixture。
4. 检索：准备带确定证据锚点的中英文问题集，检验中文问题能找回英文来源；记录失败类型，再决定是否需要 embedding。

P0 不接入真实 API 也能通过假译文验证几何和任务行为。GLM 集成测试另行使用用户授权配置，当前不收集密钥。

### P1：本地阅读闭环

Mac / iPad 工程、书库、本地 PDF 和 arXiv 导入、质量检查、渐进翻译、固定页、手写、任务恢复与设备 Keychain 配置。通过至少 12 份许可明确的样本，覆盖 HTML、普通单/双栏、复杂数学、长表格、代码、缺资源和扫描件；不能转换的样本必须正确回退。

### P2：研究工作流

当前论文优先的 RAG、辅助笔记检索、自动 Memory、Obsidian 手动保存及讨论确认、阅读日历。关键验收包括引用正确、记忆删除不复活、用户笔记不丢失、重复保存幂等和时间去重。

本地阶段提供版本化导出/导入包，用于验证页面、笔迹、锚点和记录在两端保持一致；导入先校验清单与哈希，重复导入按 ID / revision 去重，冲突保留分支，不覆盖原库。

### P3：会员与完整多端版本

会员可用后添加 CloudKit 配置、真机同步与朋友分发。至少使用两台设备验证离线并发、附件部分到达、同文不同版式、账号切换、记忆删除和配额失败；使用不同账户验证朋友之间的数据隔离。

## 14. 评审重点与自查

用户需要重点评审：固定页面首次显示即冻结、换字号新建版式的体验；原始 PDF 降级边界；GLM 服务与视觉能力的关系；先本地后 CloudKit 的阶段安排。

初次自查已检查需求映射、可变内容与固定页矛盾、Mac/iPad 独立处理、同步/会员依赖、记忆删除、Obsidian 并发保留和失败恢复。尚需实验的事项均已归入 P0 或 P3，不作为已验证承诺；iPadOS 18 保留为明确的产品假设。
