# AI 重排真实模型验证

日期：2026-11-15。用户明确授权使用应用已保存的模型和 API Key。此记录验证新设计的接口可行性与延迟，不代表新流程已经接入应用。

## 环境与方法

- macOS 15.7.7、arm64；模型 `glm-5.3-flash`，服务 `open.bigmodel.cn`，temperature 0.2，max_tokens 8192，SSE 流式请求。沿用已保存的配置，不修改用户设置或论文库。
- 临时 Swift 探针复用仓库 `KeychainStore`，只在进程内读取指定配置所关联的密钥；密钥未写入脚本、文件、命令参数、日志或模型输入。禁止重定向携带凭据。思考正文不持久化，只记录首次到达时间及供应商返回的计数。
- 全部素材原创：一个跨页文字样例含标题、未闭合句、数值/否定/限定结论、行内公式、引用、图片、图注、表格与页脚；另一个程序绘制的双栏图片含 10 行文字，供设备端 Vision OCR 与模型视觉输入使用。
- 输出采用设计中的 NDJSON 事件。检查字段白名单、事件顺序、完整结束、源 ID/UTF-16 范围、唯一归属、资源引用、公式/引用保护、正文与图件的真实阅读顺序。通过人工阅读译文，检查数字、否定和初步结论没有被改成确定结论。
- 每个变体仅运行一次；部分变体复用前缀缓存。时间从发出 URLSession 请求至客户端接收事件计算，不包含应用 UI 渲染。首个中文增量可能是标题，不等于正文或首屏可读；正文时间单独列出。

v1 同一提示的默认/disabled/low 对照说明：显式设置确实减少了本样例的等待，但没有消灭所有思考 token；不能把较快的两个错误结果当作可交付内容。

v2 明确禁止发布未闭合跨页句子、空资源图表块，并要求图注紧随对应图件。fast-v2 通过，但 low-v2 把结果段落移到表格后，仍不通过原始阅读顺序核验。测试中补充了完整顺序真值检查，因此“JSON 解析成功/基本校验成功”与最终 PASS 严格区分，表中均为最终结果。

v3 在 v2 基础上加入由该原创单栏样例的页码和 y 坐标确定的局部先后关系，不指定译文或模型分块答案。模型仍负责跨页合并与翻译；本地逐边核验源与图件顺序。fast-v3 共返回 21 条事件、6 个块，所有原文范围、对象和顺序核验通过；首次中文增量 5.04 秒，首个完整标题 5.32 秒，首个完整正文 7.69 秒。最后一项比基线增加了提示与输入约束，并命中 576 个缓存 token，不能将全部速度差异归因于单个开关。

示例中“我们使用来估计得分”的纯文本检查输出省略了独立 `object_ref`，不是漏译公式；把受保护的原公式对象嵌入后才构成完整的阅读内容。本轮未将这一对象嵌入效果作为应用视觉验收。

## 局部图片与真实 OCR

程序生成一张 1200 × 1000 的原创双栏图，Vision 本地识别 10 行约耗时 0.61 秒。去除空白差异后与绘制原文逐行一致；保留识别框、UTF-16 长度与候选置信信息。该结果只覆盖清晰的合成样例，不说明真实扫描论文的 OCR 成功率。

将逆序排列的 OCR 片段及原图片通过当前模型的图片输入接口发送，模型恢复标题、完整左栏、完整右栏顺序，页脚单独隐藏，数字与否定结论保留。9 个文字块与 38 条事件通过检查。这次使用缺省思考参数：29.66 秒开始结构化内容、34.01 秒首次中文增量、47.63 秒结束，报告 2105 个 reasoning tokens。视觉输入实际可用，但尚未测试该视觉样例的快速参数配置。

## 真实中断与续接

使用 v2 快速配置，在收到标题和首个正文的两个完整 block_end 后，约 7.51 秒主动关闭网络会话。将已结束块的原始字节与计划写入本地检查点，丢弃未完成片段。

第二个真实请求携带已接受计划和已完成索引，使用新的 request_id，要求只输出剩余块。8.21 秒结束；四个剩余块编号保持不变，计划逐字段相同，原始已保存前缀哈希不变，没有重复输出已完成块。

这只验证了协议层的续接机制。该次中断流的初始计划把图件提前到结果段之前，合并全文仍不通过顺序真值检查；正式应用必须在保存第一块之前拒绝该计划。本次结果不能表述为端到端恢复通过，也没有执行应用数据库崩溃恢复、HTML 原子提交或 UI 重新打开测试。没有为了让测试变绿而修改实际收到的原计划或正文。

## 参数结论与设计修正

现有应用请求和首轮探针均未显式设置 thinking/reasoning_effort；官方文档说明此模型系列仅支持开启思考，reasoning_effort 默认 max，可选 low/high/max。[官方接口](https://docs.bigmodel.cn/api-reference/模型-api/对话补全.md)；[模型说明](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash.md)

实际端点接受 `thinking: {"type":"disabled"}`，并在本轮显著减少思考量，但仍报告 19–96 个 reasoning tokens（不同完整快速请求）。服务接受参数不等于遵守“零思考”的语义，不能仅据 HTTP 200 标记支持彻底关闭，也不能以提示词“不要思考”替代请求能力验证。

新版流程应显式选择并记录低延迟配置；普通翻译/重排不沿用默认 max；输出仍需严格校验，来源顺序的确定部分由本地约束。当前可评估已测的 disabled 快速配置，若模型/端点变化，重新核验支持情况；不能保证零思考或稳定首屏耗时。本轮未更改用户已保存模型、旧翻译接口的生产行为或设置 UI。

## App 正式请求与原生 JSON 模式补测（2026-11-15）

接入应用后发现此前 NDJSON 只是提示词约定，没有发送 API `response_format`，不能称为 API 原生结构化输出。正式 ModelClient 在原创三段 fixture 上曾通过，首个译文增量 11.51 秒，全部三块 19.34 秒；实际 Mac 应用的两页原创示例曾在提交八块后遇到模型事件格式错误，手动继续后共十九块完成，前缀保留。此记录是旧 NDJSON 路径的实测，不能作为新格式结果。

已查阅 [GLM 结构化输出](https://docs.bigmodel.cn/cn/guide/capabilities/struct-output) 和 [对话补全 API](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)：官方文档提供 `response_format: {"type":"json_object"}`，没有列出可依赖的严格 `json_schema`。新的传输格式改为单一 `{"events":[...]}`，流式解码完整数组元素；不等待整个 JSON 完成才显示。JSON Mode 约束 JSON 格式，原文覆盖、来源 ID、公式/对象和事件顺序仍由本地校验。

已对配置的官方 `glm-5.3-flash` 做最小两句原创输入实测：`stream:true`、`response_format:json_object`、`thinking:disabled` 组合成功，输出合法 JSON，首内容 0.97 秒，共 130 tokens。该极小请求用于验证参数组合，不代表论文冷启动性能。测试日志/响应仅在本地忽略目录 `.local/native-json-probe*`；密钥只从 Keychain 读入内存。


原生 JSON 封套接入正式 `ModelClient.reflowAndTranslate` 后，使用同一原创三段 fixture 再测一次：3 块全部通过结构与提交校验，首译文增量 5.79 秒，整批 13.89 秒。与前一 NDJSON 请求不是受控重复基准，缓存与服务负载可能不同，因此只记录本次观察，不将差值归因于 JSON Mode。本轮明确保留了 `thinking:disabled` 请求参数及其“不保证实际零思考”的边界。


新版 JSON Mode 在独立验收 Mac App 中再次生成两页原创示例，十九块完成，加载页自动进入正文，观察时仍处首段。该轮观察未见结构错误暂停；不以单次成功承诺协议永不失败。发现末尾两个英文标题被模型原样复制到译文。用户明确要求只约束模型提示，不增加专用校验；最终只增加“需要翻译的标题和正文不得原样填入译文，专有名词、缩写和公式可保留”的提示。常规 JSON/来源/公式校验保留，不增加内容复制检查。没有将单个示例视为完整忠实度评测。
